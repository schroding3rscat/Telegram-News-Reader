# Мержер телеграм каналов

Это проект, который должен читать каналы в телеграме, убирать рекламу, дубликаты контента и постить все в отдельный канал через форвард сообщений.

## Требования

Сервис написан на Go. Используем последнюю версию.
У сервиса есть админка, в которой должен быть следующий функционал:
- Настройка канала, куда постить сообщения.
- Настройка бота телеграма, который будет постить сообщения.
- Возможность добавить/удалить новый канал в список читаемых.
- Отображать список читаемых каналов (урл, название).
- Админка открывается только при запросе с особым константным токеном в query (прописывается в yaml-конфиге). Без токена вернуть 404 для любой страницы. 
- Нужно запросить логин и пароль чтобы зайти, прописываются в yaml-конфиг.
- В админке также есть список соообщений, распознанных как реклама. В списке канал-источник, само сообщение и кнопка "это не реклама", чтобы пометить сообщение как false positive.
- В админке есть список тем, которые не интересны.
- Нужно обеспечить "мастер настройки" при первом открытии.

Все страницы и ассеты админки должны быть сосредоточены внутри бинаря с сервисом через embed файлов.

Go-код должен использовать fiber для рест-сервиса. Нужно исследовать, какие решения есть чтобы читать каналы ботом из-под "пользователя", потому что стандартному боту это делать запрещено.

Получаем из выбранных каналов новые сообщения. Те, что распознаны как реклама, складываем в отдельное хранилище, чтобы потом их посмотреть в админке. Те что нет, постим ботом в выбраный канал. Если сообщение - дубликат, пропускаем его. Под пересланным сообщением должны быть кнопки:
- "это реклама", которая помечает сообщение как рекламу.
- "тема не интересна", которая помечает тему сообщения как неинтересную.

Дубликаты определяем так: есть период в неделю, который является "окном" проверки. Всю эту неделю мы фиксируем в хранилище в нужном виде (необязательно целиком) сообщения и/или хэши картинок, позволяющие выявить дубликаты. За пределами окна сообщения удаляются.

Необходимо продумать персистентное хранилище под это из имеющихся opensource решений.

Определение рекламы и неинтересных тем делается через локальную LLM. Нужно исследовать и дать рекомендации какую LLM можно взять под это. Она должна потреблять немного ресурсов, тренироваться по пути тем, что размечает пользователь. Сервис на Go должен взаимодействовать с этой LLM для всех своих нужд.

Все это должно деплоиться через скрипт на VM с линуксом. В нем должно подниматься все что необходимо сервису. Скрипт должен запросить логин и пароль для админки, а также секретный токен для query. И прописать их в конфиг для сервиса. Сам сервис должен работать как systemd unit на VM, где он разворачивается.

Нужно задать вопросы, которые пропущены в требованиях.
